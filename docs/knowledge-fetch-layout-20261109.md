# 知识获取修复与 freellm 正文排版

需求：解决线上抓取问题，整理知识详情排版，使用已配置的 freellm；用户明确要求按全量知识库推进，不因免费模型用量缩减覆盖。

## 实现与验收

- 采集队列按当前栏目范围处理中国疾控旧链接；HTTP 200 的不相关内容单独记 filtered，原始快照保留。404/410 记 gone，只有来源重新提供较新的 lastmod 才重新入队。403/429 连续三次时记录错误并推迟剩余队列，避免对被阻止的站点连续请求。保留真正失败计数。
- 修复解析器后可通过 `syncAuthoritySource(id, 'incremental', { reprocessUnchanged: true })` 强制取得完整正文，避免 304 导致遗漏内容无法重新处理。正常轮次继续使用条件请求。
- freellm 只标注原文段落编号范围和类型。服务端重建文本，要求所有段落按原顺序完整覆盖，再逐字校验（只容许空白差异）；不接收模型提供的改写文字。模型输出不能直接生成 HTML，渲染时转义文本。
- 后台以实际展示的中文正文或译文为输入，每批 30 篇、最多 3 个并发模型请求；每篇完成后原子保存缓存。活跃批次间隔一分钟，空闲或批次错误间隔十五分钟，单篇失败六小时后重试。成功记录每天检查来源版本；变化后重新生成。只启动一个缓存写入进程。
- 文章 GET 仅取与当前正文指纹一致、重新校验通过的缓存，无模型等待。后台读取使用本机请求标记以避免额外累计阅读量。图片、原有表格和链接保持原有富文本；超过 60,000 字符或 500 段的内容使用原有排版，不截断。
- 网页正文卡片最大 880px，标题/段落/行距统一、左对齐；目录从实际渲染结果生成并绑定锚点。移动端目录单列，320/375/768/1440px 检查溢出。Worker 服务端正文也使用同一已验证排版。

无依赖和数据库结构变更。专用 freellm 配置使用现有 `AI_KNOWLEDGE_FORMAT_URL/KEY/MODEL/PROVIDER`；`KNOWLEDGE_AI_LAYOUT_ENABLED=true` 控制展示，`AI_KNOWLEDGE_FORMAT_TIMEOUT_MS=60000` 控制后台请求超时。代码没有配置其他模型作为该任务的备用链。

## 详情超时的性能补修

追加真实中文页面检查时，母乳喂养文章在手机上出现一次接口超时，呈现“加载文章失败 / 请求超时 / 重新加载”；没有触发脚本错误页。单篇详情在服务器本机连续测量为 3,542 / 5,112 / 5,091 毫秒。Node CPU profile 显示重复的全库过滤、文本规范化、句子拆分和富文本准备；同进程控制器调用基线为 3,337 / 2,657 / 2,615 毫秒。

为规范化后的权威记录及准备好的文章数组加入最多 60 秒的进程缓存。来源文件 mtime 变化立即重建；阅读量写回不触发正文重新准备，仍更新返回的阅读量。用户点赞状态、译文和排版缓存仍按请求读取。回归测试验证连续读取复用结果、来源更新刷新正文。
