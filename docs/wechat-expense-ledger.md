# 微信孕育记账月账（2026-09-23）

入口：工具目录 → 孕育记账。已有账目显示月份合计和明细，录入默认收起；空账本展开录入。月账按实际发生日期统计本机保留记录，打开详情后可从历史查看全部类型、原分类、日期与备注。金额/备注不进入分析埋点。

## 统计口径与旧记录

- 正金额表示一笔支出、退款或转账，金额输入最多两位小数、单笔 0.01–1,000,000 元。逐笔转整数分后累计，再格式化为元。净支出可以为负；这表示本月已记录退款多于支出，不推断收入。
- 退款按到账月份扣减，不回改原消费月份；转账合计单列，不计入支出、退款、净支出或分类占比。占比使用支出总额为分母，显示到 0.1%，可能存在四舍五入差异。
- 旧本机手动表单只支持支出，因此无类型的本机记录兼容为支出；旧云端记录丢失类型时不猜测，列入全账本“待核对旧账”。无效日期、金额和类型也列于此处，保留原记录入口。确认后可补记，再移除错误旧账。
- 旧自定义分类汇总为其他/未分类，原分类仍在明细和历史中展示。摘要不另存副本，记录变化后重新计算。
- API 转换仍使用既有 amountCents、direction、occurredAt 字段；退款和转账的类型进入历史及发送前的 AI 回顾正文。早期已经丢失的类型只能在未来重新同步或人工核对后恢复，不能从金额猜测。

## 验证

逻辑测试：expense-ledger.test.ts 覆盖 6 个场景，含精度、0.1＋0.2、负净支出、退款独立归月、转账排除、闰日/无效日期、旧数据、记录更新删除、接口往返和 AI 回顾类型。

浏览器脚本在独立 Playwright context 写入合成记录，所有 beihu.me 请求使用本地响应桩，不调用生产模型、不访问真实账号数据。覆盖快速改金额后立即保存、三种类型、月份与筛选、历史定位删除、分页、存储失败、账号变化与窄屏。日期及分类选择用 uni-app change 事件检查页面逻辑；原生选择器不计为通过。

运行方式（Playwright 安装在独立工具目录时通过 NODE_PATH 指向其 node_modules）：

    npm --prefix mini-program run dev:h5 -- --host 127.0.0.1 --port 5198
    NODE_PATH=/path/to/ui-test/node_modules node mini-program/scripts/check-expense-ui.cjs

脚本截图默认写入系统临时目录 beihu-expense-ui，可用 BEIHU_UI_OUTPUT_DIR 指定。检查表单使用 form submit 的当前值，避免依赖存在输入节流的 v-model；这是快速更正金额回归测试要守住的行为。
