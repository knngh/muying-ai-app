# 微信端候选名对比与 AI 匹配评分

本版在已有预生成起名库上增加“加入对比 → 选择风格 → 资料对比 / AI 评测 → 本机历史”。不提供自由输入名字或实时生成新名字。候选库仍为小规模预览样本，资料待人工复核。

## 评分和模型

- 每次选择 1–5 个已有候选名，同批使用相同姓氏；风格选 1–3 项：清雅、明朗、稳重、温柔、简洁、书卷感。
- Jev 使用一批最多 15 个闭集问题，逐一选择 1–5 级或 `unknown`。只发送库内名字、释义和风格问题，不向模型发送姓氏、账号资料、生日或家庭信息。
- 置信度不足 0.6 的维度显示“待评”。全部维度可评分时，代码计算等权平均并四舍五入；部分维度待评时不计算综合分。没有可靠结果时只展示资料，不能以默认 3 分冒充 AI 评分。
- 数字表示本次风格匹配程度，不是名字优劣、人口热度或吉凶结论。结果保留输入顺序，不冠以“最佳名字”。
- 读音、字数、含义、参考原句从库内读取；声称出处真实、姓氏连读顺畅、方言谐音安全，都超出当前能力。页面列出需要家人核对的项目。
- 中文说明使用固定句式，本版只调用 Jev。需要自由中文解释的后续版本才考虑官方 GLM-5.3，同时独立验证新增事实和出处幻觉；本版没有这条调用链。

## API

`POST /api/v1/names/evaluate`，登录认证、既有 AI 限流、严格 Zod 校验、服务开关、既有配额控制后执行。

```json
{
  "surname": "欧阳",
  "candidateIds": ["jing-shu", "yun-fan"],
  "preferences": ["温柔", "明朗"],
  "consent": true
}
```

只接受当前库内且不重复的 ID，以及既定风格；不接受客户端传入的释义、出处、提示词或分数。响应契约位于 `src/data/name-evaluation.ts`，共享类型从该处导出。返回 `source: ai | rules`、库版本、候选资料、可空分项分数、可空综合分和说明；缓存策略为 `no-store`。供应商错误正文不回传。

本接口不会持久化姓名或结果到服务器数据库。既有配额系统仍记录使用次数等计费元数据。微信端只有用户确认后才发起本次评测，不自动重试收费请求；网络错误保留已选项，可手动重试或使用资料对比。

## 本机记录和界面

- 原名字卡增加“加入对比”，底部显示已选数量和“去对比”；继续使用原暖色和字级。
- 对比区显示可移除的候选名、风格选择、离线资料对比与 AI 评测两个动作。
- 结果显示 1–5 级条形指标和文字数值，无依据时显示破折号。所有结果均保留来源说明。
- 两种结果均保留最近 10 次到本机，可在“历史记录”展开查看和确认删除；收藏独立保存。
- 已选候选名与风格偏好在重新进入或登录返回后恢复。存储失败明确提示“未能保存”，不会假装成功。
- 读取历史时校验记录结构并重建库内事实；无效记录及库版本不兼容的记录不展示，升级候选库时应重新评测。

## 开关与发布状态

后端：`NAME_EVALUATION_AI_ENABLED=true`。

微信端构建环境：`VITE_NAME_EVALUATION_AI_ENABLED=true`。

两者默认关闭，资料对比照常可用。与 `VITE_NAME_LIBRARY_CLOUD_ENABLED`、工具记录 AI 开关彼此独立。先部署接口，再开启微信端，避免调用尚不存在的路由。

2026-09-21 首批后端已部署，生产开关保持关闭；未上传微信版本。发布范围、验收和回滚见 [首批发布记录](./tool-ai-batch1-release.md)。AI 评测属于实际 AI 功能，不能因名字来自离线库就宣称免于标识或类目要求；正式开放前应按实际主体、服务形态和微信审核规则核验，界面已保留 AI 标识和发送前说明。

## 验证

相关单测覆盖请求边界、认证、配额顺序、默认关闭、固定候选、低置信度、供应商失败及历史恢复。实际 Jev 脱敏样本调用成功，返回部分评分和低置信度待评项；这只证明链路可用，不代表中文风格评分质量已经完成系统评测。

2026-09-21 前期本地验证：相关 6 个测试套件共 31 项通过；后端构建、lint、微信端类型检查和微信构建通过。微信开发者工具自动化验证了选择 2 个候选、最多 3 项偏好、资料对比保存、重新进入后的草稿与偏好恢复、展开历史和删除，未捕获运行异常。重新构建期间开发者工具曾出现缓存错配及自动化连接断开，清理编译缓存并重启项目后，上述流程复测通过。首批后端发布时扩大到 12 个相关套件、74 项测试并通过线上验收；未进行手机真机验证或微信版本上传。
