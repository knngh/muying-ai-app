# 疫苗与孕育日历提醒

2026-09-22 增量。仅修改微信端及必要后端；代码已完成队列闭环，但未部署、未上传微信版本、未配置微信消息模板或启动生产 worker。

## 当前可用链路

- 首页会显示当前账号/游客本机的提醒摘要；仅有待处理提醒时出现，不改变原有日历与档案卡片。提醒在 24 小时内或已经到点时显示一次可关闭提示，关闭状态按提醒版本保存。点击摘要会打开日历的“提醒”标签；这只是小程序打开时的本机提示，不代表后台消息已发送。
- 日历保留原周轴与卡片，增加“提醒”标签；各未完成待办有“设置提醒”，带入实际待办名称，不把孕周参考节点当作已确认就诊日期。
- 疫苗记录选择“已预约/待确认”保存后进入提醒设置。待接种安排支持再次设置提醒及标记今日已接种，原预约日期仍保存在历史详情。其他接种日期可单独补记并停止原预约提醒。
- 双端使用同一份本机提醒数据。按每条接种记录 ID 或日历待办的阶段/键关联，改期更新原提醒，不用疫苗名称做去重，避免不同剂次互相覆盖。
- 可选准时、提前 1 小时、1 天、3 天、1 周，显示实际提醒日期与时刻；提醒时刻已过去时拒绝保存，要求调整安排。
- 到点后标记“已到提醒时间”，不伪称已发送。日历待办完成/删除后结束关联提醒；标记某剂已接种或删除该接种记录，仅结束该条提醒。恢复待办不会擅自恢复已结束提醒，需要重新安排。
- 手工新建的提醒可以完成/停止，已结束列表可查看、删除或重新安排。每个账号/游客最多 200 条，满后明确提示清理，不静默淘汰待执行提醒。

## 小程序内展示与手机系统通知

点击“加入手机日历”才调用微信 `wx.addPhoneCalendar`，请求系统日历授权。开始时间和 `alarmOffset` 都按接口要求传秒数。授权失败、取消或不支持时保留本机记录，不标记成功；只有成功回调才标记已加入。

接口不提供已创建日程的 ID，也不提供由小程序删除/更新该副本的对应接口。本机改期、完成、停止、删除后，页面明确提示用户在手机日历同步处理；不会声称已取消系统通知。改期保留之前导出的签名，显示手机日历仍有旧安排。用户的日历通知、系统权限和系统日历同步设置决定实际送达。

微信订阅消息代码链路已补齐，但默认关闭。小程序只有在 `VITE_WECHAT_SUBSCRIBE_ENABLED=true` 且配置模板 ID 时才调用 `wx.requestSubscribeMessage`；用户同意后才把提醒排入服务端队列。后端再次校验模板 ID、openid、时间和提前量，并以 `(userId, clientReminderId)` 做幂等键。改期会重置同一队列记录，完成/停止/删除会取消 `pending/sending/failed` 记录，不会伪造“已发送”。

发送 worker 为独立进程 `npm run worker:wechat-reminders`，只有 `WECHAT_SUBSCRIBE_ENABLED=true`、微信应用凭证、模板 ID 和三个模板字段都齐全时才启动。worker 领取任务时使用条件更新避免重复发送；成功标记 `sent`，临时失败按 `WECHAT_REMINDER_MAX_ATTEMPTS` 重试，明确的模板/拒绝错误直接标记 `failed`，超时的 `sending` 会回收。`src/scripts/run-wechat-reminder-worker.ts` 不会由 Web API 进程自动启动。

## 存储与隐私

本机储存键：`beihu:reminders:v1:<owner>`。本机工具记录使用 `beihu:tool-records:v2:<owner>`，旧全局记录只留在游客空间，不自动迁移到登录账号。微信队列只保存当前账号的提醒标题、时间、提前量和状态；openid 只用于发送，不写入日志或返回小程序。提醒标题、日期和提前量只有用户主动授权微信订阅或加入手机日历时才离开设备，不读取其他日程。隐私指引已同步补充用途与取消边界。

原始工具记录与提醒分别写入本机；如果原记录已保存而提醒更新失败，会提示在提醒列表手动停止，不能把原记录误报为未保存。手机日历成功回调会校验原安排签名，防止较晚回调将改期后的安排错误标记为已导出。

## 验证与后续

- 提醒逻辑测试覆盖 9 项行为：无效日期/时间、跨月/跨年提前量、已过提醒时间、重复修改、账号隔离、手机接口秒数、迟到回调、按剂次完成、摘要窗口与本机提示已读隔离；订阅服务另有模板校验、幂等、取消、租约、重试和默认关闭测试。
- 与日历 schema、阶段规则、回顾历史一起运行的 4 组 22 项测试通过；小程序类型检查、微信构建、新测试 ESLint 通过。
- 隔离浏览器验证疫苗预约/日历共享列表、改期不重复、待办带入、授权未成功不标记已加入、标记接种关闭对应剂次、历史重开、320/375/430 宽度及无页面脚本异常。
- 微信开发工具在独立游客测试项目中验证：预约保存后打开提醒编辑器，日期/时间/提前量持久化，模拟授权失败不标记已加入，模拟成功才标记已加入；实际截获的接口参数为正确的 Unix 秒数和 86400 秒提前量，日历页可重开同一提醒。订阅消息未配置时不会调用授权或后端队列。模拟调用没有写入真实手机日历。脚本及截图位于 `/private/tmp/beihu-review-ui-check/`。
- 手机日历授权、通知权限、实际响铃以及各品牌手机兼容性仍需真机验收。测试过程中不向真实手机日历写入事项，不发送任何微信订阅消息。
