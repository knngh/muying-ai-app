## 2. 代码迭代工作流（Dev）

### 2.1 分支策略

```
main (生产) ──── 稳定，只接受 PR
  │
  └── dev (开发) ──── 日常开发
        │
        ├── feat/xxx ──── 功能分支
        ├── fix/xxx  ──── 修复分支
        └── chore/xxx ──── 运维/工具分支
```

**规则**：
- `main` 分支永远可部署，只通过 PR 合入
- 一人开发时 `dev` 分支可快速自合并，但保持 PR 习惯（写清改动摘要）
- 每个功能/修复控制在 1-2 天内可完成的大小
- 合并前必须跑 `npm run test:unit && npm run lint`

### 2.2 开发节奏

| 节奏 | 动作 | 时长 |
|------|------|------|
| 每日 | 拉取最新 dev，完成当日功能/修复 | 2-3h |
| 每周二 | 代码 review 自检（看本周 diff） | 30min |
| 每两周 | 技术债务清理（挑 1 个小项） | 2h |
| 每月 | 依赖更新（`npm outdated` → 逐个升级测试） | 1-2h |

### 2.3 发布流程（已有脚本）

```bash
# 1. 本地验证
npm run lint && npm run test:unit

# 2. 同步到生产
npm run ops:sync:prod

# 3. 部署
npm run ops:deploy:prod

# 4. 烟测验证
npm run ops:smoke:prod
npm run ops:smoke:uploads
npm run ops:smoke:ai

# 5. 如有问题，立即回滚
npm run ops:rollback:prod
```

### 2.4 代码迭代优先级矩阵

```
                    影响大
                      │
         P0 紧急修复    │    P1 核心功能
         (当天必须)     │    (本周完成)
                      │
  ─────────────────────┼─────────────────────
                      │
         P2 体验优化    │    P3 技术债务
         (本月完成)     │    (下月或排期)
                      │
                    影响小
```

**当前 P1 清单（基于项目现状）**：
- [ ] App 端首日激活引导优化（降低流失）
- [ ] 小程序分享链路参数补全（channel/campaign/scene）
- [ ] 权威知识库覆盖率从 82% → 85%

**当前 P2 清单**：
- [ ] AI 提问历史查看优化
- [ ] 社区入口恢复（按节奏）
- [ ] 前端性能优化（首屏加载）

## 3. 服务运维工作流（Ops）

### 3.1 日常巡检（每天 10min）

```bash
# 一键健康检查
npm run ops:smoke:prod                    # API 健康检查
npm run ops:smoke:ai                      # AI 通道健康检查
npm run ops:knowledge:status              # 知识库运营状态
npm run ops:growth:p7                     # 增长数据报告
```

**关注指标**：

| 指标 | 健康值 | 告警阈值 |
|------|--------|----------|
| API 健康检查 | 200 OK | 非 200 |
| AI provider 可用 | `status=ok` | `degraded` 连续 2 次 |
| 知识库覆盖率 | ≥80% | <80% |
| 翻译缓存命中率 | ≥40% | <30% |
| 翻译失败条数 | 0 | >5 |

### 3.2 每周运维（每周一 30min）

| 步骤 | 命令/动作 | 输出 |
|------|-----------|------|
| 1. 知识库日报 | `npm run ops:knowledge:daily` | `tmp/knowledge-daily-ops-report.json` |
| 2. 知识库周报 | `npm run ops:knowledge:report` | `tmp/knowledge-ops-report.json` |
| 3. AI 运维报告 | `npm run ops:ai:report` | `tmp/ai-ops-report.json` |
| 4. 权威源同步 | `npm run sync:authority` | 更新权威缓存 |
| 5. 翻译失败重试 | `npm run retry:authority-translation-failures` | 清理失败队列 |
| 6. 归因覆盖率检查 | `npm run ops:growth:p7` | P7 增长报告 |

### 3.3 每月运维（每月 1 日 1h）

| 步骤 | 动作 |
|------|------|
| 数据库备份验证 | 从备份恢复到临时库，验证数据完整性 |
| 日志归档 | `tmp/` 目录下超过 30 天的报告归档或清理 |
| 依赖安全检查 | `npm audit` 处理 high/critical |
| 服务器资源检查 | 磁盘/内存/连接池使用率 |
| 权威覆盖率审计 | `npm run audit:authority-coverage` |
| 翻译缓存清理 | `npm run clean:authority-cache` |

### 3.4 告警与应急

| 场景 | 检测方式 | 应急动作 |
|------|----------|----------|
| API 挂掉 | 烟测失败 | `npm run ops:rollback:prod` |
| AI 通道降级 | `ops:ai:health` 返回 degraded | 检查 DeepSeek 余额/切换 provider |
| 知识库覆盖率下降 | `ops:knowledge:status` | `npm run sync:authority` 补充 |
| 支付回调异常 | `ops:verify:payment-callback:prod` | 检查支付网关配置 |
| 数据库连接池耗尽 | 服务日志 | 调整 `connection_limit` 或重启 |

### 3.5 建议新增的自动化（优先级排序）

| 优先级 | 自动化项 | 实现方式 | 预计耗时 |
|--------|----------|----------|----------|
| P0 | 每日自动烟测 + 结果推送到微信/邮件 | cron + 脚本 | 2h |
| P0 | AI provider 余额/降级自动告警 | 现有 `ops:ai:health` + 通知 | 1h |
| P1 | 数据库自动备份 + 每周验证 | crontab + mysqldump | 1h |
| P1 | 磁盘空间监控（uploads 目录） | 简单 df 脚本 | 30min |
| P2 | 日志自动轮转归档 | logrotate | 30min |

## 4. 内容运营工作流（Content）

### 4.1 知识库运营（核心差异化资产）

**节奏**：

| 频率 | 动作 | 命令 |
|------|------|------|
| 每日 | 权威源增量同步 | `npm run worker:authority`（已在跑） |
| 每周 | 翻译失败重试 + 缓存修复 | `npm run retry:authority-translation-failures` + `npm run repair:authority-translation-cache` |
| 每两周 | 低覆盖率来源刷新 | `npm run ops:authority:refresh-low-coverage` |
| 每月 | 权威覆盖率审计 + 增长种子 | `npm run audit:authority-coverage` + `npm run plan:knowledge-growth` |

**知识库增长目标**：

| 阶段 | 目标覆盖率 | 当前 |
|------|-----------|------|
| P3 ✅ | ≥80% | 81.99% |
| 当前目标 | ≥85% | 推进中 |
| 长期目标 | ≥90% | 需要更多来源适配 |

### 4.2 内容创作矩阵

你的核心内容资产是**权威知识库**，围绕它做内容而不是从零创作：

| 渠道 | 内容形式 | 频率 | 复用来源 |
|------|----------|------|----------|
| 小红书 | "孕 X 周必须知道的 3 件事" | 每周 2 篇 | 知识库按孕周筛选 |
| 微信社群 | 每日一条阶段提醒 | 每日 | 知识库 + 孕育日历数据 |
| 抖音/视频号 | 30s 红旗症状急救 | 每周 1 条 | AI 问答高频问题 |
| 公众号 | 月度孕育指南 | 每月 | 权威文章 + 翻译 |

**内容创作流程（单人 30min/篇）**：
1. 从 `npm run ops:knowledge:daily` 的报告中找本周高频问题
2. 用 App 自己的"问题助手"生成结构化答案
3. 人工审核：确认来源、风险分级、就医提醒正确
4. 改写为对应平台格式发布
5. 在 App 内创建对应知识库入口，引流回 App

### 4.3 知识库 → 推广素材转化

```bash
# 1. 查看当前知识库热门问题
npm run ops:knowledge:report

# 2. 生成权威 QA 增补
npm run topup:authority-qa

# 3. 导出推广候选池
# 从 knowledge-ops-report 中提取高搜索量 + 低覆盖问题
```

## 9. 一人公司生存法则

### 9.1 精力分配原则

```
开发 30%  ──── 保持迭代但不过度工程
运维 10%  ──── 自动化后尽量少花时间
内容 25%  ──── 知识库是核心差异化资产
增长 25%  ──── 没用户就没有一切
商业 10%  ──── 验证付费意愿，不过早优化
```

### 9.2 说不的清单

作为一人公司，以下事情**现在不做**：

- ❌ 多语言国际化（先把中文做透）
- ❌ 社区功能扩展（当前聚焦知识库 + AI）
- ❌ 自建 AI 模型（用第三方 API 即可）
- ❌ 过度设计微服务架构（单体足够）
- ❌ 同时运营 4+ 个社交媒体渠道
- ❌ 在没有 100 个活跃用户前优化变现细节

### 9.3 一人公司节奏 vs 疲劳管理

| 信号 | 含义 | 行动 |
|------|------|------|
| 连续 3 天没写代码 | 可能进入倦怠期 | 减少开发，多做内容和用户交流 |
| 1 周没看数据 | 增长在脱轨 | 回到日报习惯 |
| 功能越做越多但用户没涨 | 过度工程 | 停止开发 1 周，只做增长 |
| 每天都在灭火 | 运维不够自动化 | 花 1 天集中写脚本 |
